هذا المستودع يحتوي الآن على Workflow مستقل ينشر `www/` مباشرة على GitHub Pages حتى يظهر التطبيق نفسه، وليس README. عنوان الموقع المتوقع: `https://iapiaap91-svg.github.io/intissar_ai/`.

# انتصار AI — نسخة Android (Capacitor)

تطبيق Android حقيقي (APK) مبني من نفس `www/index.html` (تطبيق الويب)، عبر
Capacitor، بحيث يخدم **Offline بالكامل** بعد التثبيت (ماعدا 3 ميزات اختيارية
موضحة تحت).

## البنية

```
intissar_capacitor/
├── www/index.html          ← تطبيق الويب (نفس الواجهة والوظائف، معدَّل للعمل محلياً)
├── package.json            ← تبعيات npm (Capacitor + المكتبات المُجمَّعة محلياً)
├── capacitor.config.json   ← إعدادات Capacitor
├── models/vosk-models.json ← قائمة نماذج التفريغ الصوتي المحلي (Vosk)
├── native-additions/       ← كود Java مخصص (إضافة Vosk) يُزرع فمشروع android/
├── scripts/
│   ├── bundle-offline-assets.js   ← يجمع كل المكتبات/بيانات اللغة محلياً
│   └── patch-native-android.js    ← يربط إضافة Vosk بمشروع android/ المولَّد
├── .github/workflows/build-apk.yml ← يبني APK كامل تلقائياً فسحابة GitHub
└── android/                 ← ماشي موجود فالمستودع — يتولّد تلقائياً عند البناء
```

**لماذا `android/` غير موجود فالمستودع؟** لأنه يحتوي مئات الملفات
المولَّدة تلقائياً من Capacitor نفسه. الاعتماد على الأداة الرسمية
(`npx cap add android`) فكل بناء أوثق من نسخة يدوية قد تتعارض مع تحديثات
Capacitor لاحقاً.

## كيفاش تحصلي على APK

**هاذ المشروع ما يقدرش يتصرّف (compile) فبيئة Claude** — يحتاج Android
SDK وGradle واتصال إنترنت حقيقي لتحميل النماذج والمكتبات، وهاذي البيئة ما
فيهاش هذا (نفس القيد لي شرحناه قبل مع مشروع Flutter).

**الحل**: نفس أسلوب GitHub Actions المستعمَل قبل:

1. ارفعي هاذ المشروع كامل لمستودع GitHub (public أفضل — باش نقدر نقرا
   سجلات الأخطاء الحقيقية معاك إذا صار مشكل).
2. GitHub Actions يبني APK تلقائياً عند كل `push` لـ `main`، ويحطه فـ
   "Actions → (آخر تشغيل) → Artifacts" كملف قابل للتحميل.
3. لنشر رسمي: أنشئي Release (Tag) — الـ APK يترفق فيها تلقائياً.

## ⚠️ الجزء الأكثر عرضة للحاجة لتصحيح: إضافة Vosk

كتبت كود `VoskSttPlugin.java` يدوياً بلا اختبار ترجمة حقيقي (ماكاش Android
SDK هنا). هو الجزء الوحيد فهاذ المشروع اللي يحتمل يحتاج جولة تصحيح واحدة
أو اثنين — بنفس الطريقة اللي صلّحنا بيها `release.yml` قبل: ابعتيلي رابط
أي عملية بناء فشلت (Actions run) ونقرا الخطأ الحقيقي بنفسي مباشرة.

## قائمة الميزات وحالتها Offline (كيما طلبتي بالضبط)

| الميزة | الحالة Offline | التفاصيل |
|---|---|---|
| تسجيل صوتي | ✅ كامل | MediaRecorder — محلي 100% |
| تفريغ صوتي (عربي/فرنسي/إنجليزي) | ✅ كامل | عبر Vosk محلي (نموذج مُضمَّن فالـ APK)، بدل Web Speech API |
| فصل المتحدثين | ✅ كامل (تقريبي) | تحليل شدة الصوت (RMS) — نفس القيد الأصلي: تقريبي وليس تعرّف هوية حقيقي |
| OCR (صور) | ✅ كامل | Tesseract.js + بيانات اللغة مُضمَّنة فالـ APK (ara/fra/eng) |
| قراءة PDF/Word/PowerPoint | ✅ كامل | PDF.js / mammoth / JSZip مُجمَّعة محلياً، بلا CDN |
| الأرشيف | ✅ كامل | localStorage محلي (داخل WebView) |
| تشفير الأرشيف | ✅ كامل | AES-GCM عبر Web Crypto API — يخدم بلا إنترنت |
| تصدير PDF | ✅ كامل | عبر معاينة طباعة النظام (لا يحتاج مكتبة أو إنترنت) |
| **"🤖 اسأل" و"🧠 اختبار"** | ✅ يخدم Offline بجودة أساسية (افتراضياً) | الوضع الافتراضي "🟢 Offline" يستعمل مطابقة نصية محلية بلا إنترنت (بلا فهم حقيقي، تماماً كالمشروع الأصلي بـ Flutter). لجودة "احترافية" حقيقية (فهم واستنتاج)، تقدري تفعّلي Gemini/Claude/OpenAI من ⚙️ الإعدادات — وهذا الخيار وحده يحتاج إنترنت ومفتاح API، وواضح فالواجهة أنه اختياري. لا يوجد نموذج LLM محلي عملي الحجم يعطي جودة مماثلة على هاتف عادي بلا إنترنت. |
| Airplane Mode | ✅ يخدم | كل الميزات فوق (ماعدا اسأل/اختبار) تخدم بلا أي اتصال |

## حجم APK — نقطة مهمة يجب معرفتها

لا يوجد نموذج Vosk "صغير" رسمي للعربية حالياً (خلاف الفرنسية/الإنجليزية
~40MB لكل وحدة) — أصغر نموذج عربي متوفر هو `vosk-model-ar-mgb2-0.4`
بحجم **~318MB**. هذا يعني حجم APK النهائي سيكون كبيراً نسبياً
(~400MB مع باقي النماذج والبيانات). إذا كان هذا مشكلة، الخيارات:
- الإبقاء على العربية فقط (حذف نموذجي الفرنسية/الإنجليزية من `models/vosk-models.json`) لتقليل الحجم.
- أو نشر APK بلا نماذج، وتحميلها من داخل التطبيق أول مرة (يحتاج إنترنت أول مرة فقط، ثم offline بالكامل) — تغيير ممكن لاحقاً إذا حبيتي.
